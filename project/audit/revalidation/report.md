# Flood Sentinel second audit: code correctness, evidence integrity and research direction

Date: 1 October 2026, Asia/Kathmandu. Baseline: commit `4e9e4be5fc56d5a905f9c53de42aaeeccd675e88`. Scope: the new working repository, migrated engine, active factory execution/checking paths, supplied Deep Research response, and the existing portable forensic evidence. Review provenance: one local coding agent using code inspection, adversarial constructed fixtures, hand calculations, external reference arithmetic and primary-source checks. This is not independent scientific certification.

## Conclusion and present state

The migrated files were **not free of errors**. The first test suite missed mutable fitted statistics, a collapsing width-one neural configuration, overflow, permissive input coercion and a training interface that did not bind the actual input mask to the loss. The supplied factory also had receipt-authentication and assurance defects that could allow false evidence acceptance. Confirmed defects have been corrected and tested. The original code/evidence hashes and failed attempts remain available.

No acquired Flood Sentinel study cohort, authentic production acquisition adapter, trained research model, future-warning benchmark, population inference, research freeze or journal-ready result exists. Absence of these artifacts is an open work package, not a reason to create substitute observations. This audit does not certify the absence of all conceivable mathematical errors, data bias or fabrication. It establishes concrete reviewed properties, exposes the remaining trust boundary, and strengthens the next-stage contracts.

The research direction is defensible if narrowed to authentic source feasibility followed by an information-matched, prospective evaluation of future-onset warning. It does not yet support a new-model or performance claim. Reconstruction scores may or may not offer advance warning; that question remains empirical. The project's strongest potential contribution is an honest evaluation of warning value under label scarcity, availability constraints and false-alert exposure, rather than the existence of a TCN/Transformer combination. A valid negative result remains possible, but cannot be inferred from invalid legacy artifacts.

### Formula/behavior checks that remain sound within their stated scope

Causal convolution uses left padding only. Per-time channel normalization does not aggregate across future time steps. Attention permits the present/past with an inclusive triangular mask, and future-value/gradient interventions verify a prefix cannot depend on a later suffix in evaluation mode. Training dropout introduces randomness; comparing independently sampled stochastic forwards is not a causality proof. Neural checks now reject nonfinite arithmetic rather than conceal it.

EA-LSTM's static input gate remains constant across a sequence, while dynamic/hidden state drives forget, candidate and output gates. The binary classifier is explicitly separate from the original paper's experimental system. [Kratzert et al., HESS 2019](https://hess.copernicus.org/articles/23/5089/2019/).

Normalization uses supplied raw training values; observed zero remains observed, missing NaN retains a mask, and imputation uses fitted training medians. Constant/unsupported channels require an explicit decision rather than an invented variance. Robust calibration rejects zero IQR/one-point fallback; latent distance uses a fitted covariance reference with declared shrinkage. The mathematical operator does not identify flood precursors by itself.

AUROC uses tied average ranks; AP integrates grouped precision changes, not trapezoidal PR area. These match an external reference over reversed/tied fixtures. AUROC without both classes remains unavailable; AP without positives remains unavailable under this project's convention. F1 uses an explicit zero-denominator convention and must not be presented as event skill in an unsupported population. Bootstrap/Holm arithmetic is not evidence that a basin/event dependence structure is correct.

Future labels preserve exact and interval-censored onset boundaries, exclude past/current onset and require complete truth for negatives. An enumerated interval-support oracle checks boundary cases without choosing a convenient midpoint. Coverage and current threshold state are still caller-supplied facts. Alerts confirm at the last required observation and break on gaps; production episode matching, cooldown/exposure and threshold history remain unimplemented.

### Corrected source feasibility facts

gridMET's official documentation describes daily updates but also replacement of recent forcing, preliminary recent values and reprocessed historical periods. Its nominal day is midnight-to-midnight MST, not automatically a UTC calendar day. This contradicts a fixed universal historical latency/vintage assumption. Read variable metadata/scale/units from genuine files; do not assume table temperature units are the native encoding. This source can support a carefully qualified retrospective study, but operational replay requires publication/vintage evidence. [Official gridMET documentation](https://www.climatologylab.org/gridmet.html).

SNODAS is model/data-assimilation output, not direct SWE observations. The user guide lists SWE/depth snapshots at 06:00 UTC, not the response's 00Z. SWE/depth binary integers scale by 1000 into meters; conversions must be tied to the actual product/header. The guide also documents an affected-cell erroneous-zero period during 2014–2019 and a repair mask: zero is not always valid physical absence. P02 must preserve quality/mask/version decisions, missing sentinels and source-specific scale/time conventions. [Official user guide, Tables 1–2](https://nsidc.org/sites/default/files/g02158-v001-userguide_2_1.pdf). This check did not retrieve a basin raster or prove vintage access.

NOAA distinguishes the NWPS application API, HEFS and the experimental NWM API. The application API does not expose general historical data beyond its stated crest/low-water history; the NWM API documents limited rolling runs. A current API/threshold response cannot establish a decades-long as-issued archive or a historic threshold/datum. NWM guidance is also distinct from official forecasts. [NOAA API description](https://water.noaa.gov/about/api).

The official retrospective NWM registry specifies v3.0 CONUS coverage from February 1979 through January 2023. Retrospective meteorological forcing and output differ from operational forecast products; the registry notes no streamflow assimilation in those retrospective simulations. Coverage must be read from actual selected objects, intersected prospectively and represented as genuine model output. Unavailable dates cannot be manufactured from observations. [NWM archive registry](https://registry.opendata.aws/nwm-archive/).

Public availability and citation information do not justify blanket CC0 licensing across providers. Preserve source-specific terms and root/inherited code licensing. The external response's date/version/license table remains unauthenticated unless backed by the exact authoritative source. The complete literature review, supplements, study inclusion rules and current venue policies still belong in P01/P14; this focused correction is not a systematic review or a promise of top-tier acceptance.

## What still prevents scientific/research completeness

1. **Source feasibility:** no new raw provider bytes, vintage archive, official-stage/datum history, static-attribute joins or rights-approved cohort has been acquired. Expose unknowns, exact feasibility exclusions and prospective collection options. A hash proves byte identity, not provider origin.
2. **Runtime/trust integration:** the typed runtime's isolation flags exclude ordinary NumPy/PyTorch imports; the argv/domain round trip remains open. Same-user signing cannot exclude worker forgery. Network declarations, child dependency/interpreter identity and hidden targets require actual enforcement or narrower assurance language. Do not bypass isolation to make a script run.
3. **Label/coverage design:** official-stage future-onset truth, current state, datum changes, interval censoring, right censoring, gaps and independent episodes need source-derived adapters. Daily aggregates cannot supply an exact hourly onset. A hydrological exceedance alternative is a separate disclosed target, not fake official stage.
4. **Cohort/split/independence:** eligible sites/dates and support counts are unknown. Split units must respect connected rivers, storms, temporal overlap and source ancestry. Legacy test knowledge and outcome-driven site choices are exposure, not untouched confirmation. Row counts cannot substitute for independent events/river systems.
5. **Learning/comparator fairness:** no real training, validation stopping trace, model selection, fitted probability mapping, calibration set, budget-matched baselines or ablations exists. Full label/unlabeled budgets and permitted target history must be charged consistently. Defaults in a primitive are provisional configurations, not adopted methodology.
6. **Operational endpoints/inference:** complete issue streams, alert merging/matching, eligible exposure, recall/false-alert/lead intervals and cluster-aware uncertainty remain to be implemented and independently recomputed. Undefined support, imprecision and infinite losses remain explicit. Do not remove failed detections or sparse basins to improve summaries.
7. **Hardware/reproducibility:** the user's M3 Air specifications are not observed sustained-training measurements. Test CPU correctness first, benchmark measured memory/throughput on a real development pilot, run seeds sequentially and preserve failures. Full source archives may exceed available disk; versioned subsetting and lawful archive/retrieval contracts are essential. No energy claim is available.
8. **Independent review and submission:** this local audit does not replace domain/statistical review. A valid result, current literature novelty, complete limitations, lawful release, replay in a fresh environment and current venue-specific requirements precede submission. A code test pass establishes none of these alone.

Keep P00–P14 in dependency order. Stop at an unidentifiable source/label/estimand rather than substitute synthetic observations. If feasibility fails, preserve the attempted queries/receipts and report the specific limitation. If the model fails in a valid experiment, retain predictions and report its direction/precision. If the method is invalid, stop the claim and repair prospectively; do not call that a scientific negative result.

An additional schema limit matters for genuine forecast inputs: `Observation` represents completed observation/analysis intervals and prohibits availability before interval end. Authenticated forecasts can legitimately be published before their future valid interval. P00/P02 therefore need a separate typed as-issued forecast/vintage representation, not a weakened observation rule or relabeling forecast values as observed truth. Confirmatory comparisons must disclose the actual issue-time information sets, including any future-valid forecast products; neither retrospective forcing nor a current API response supplies historical as-issued evidence.
