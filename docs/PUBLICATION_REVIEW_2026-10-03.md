# Project publication review — 3 October 2026

The implementation remains v3.3.0. This change separates the public project repository from private development orchestration and scientific evidence. The source distribution itself remains tracked.

Project initialization creates Git if necessary, installs neutral root allowlist rules, keeps explicit private paths in Git's local exclude file, and installs private chained commit/message/push hooks. Existing project ignore patterns survive. Linked worktrees require independent configuration rather than silently changing shared hooks. A project's ordinary bootstrap script does not exempt it from the boundary.

The scanner reads actual index blobs and exact outgoing object identities. It checks public paths, file and ref names, all reachable commit trees, commit messages and author metadata, and annotated tag metadata. It blocks recognized internal references, private files, credentials and local host paths without copying matched secrets into findings. Deleting a leaked file in a later commit does not make its history publishable. Source comments, project prose, notebooks and CI files pass through the same content inspection.

Unmerged entries, symlinks, submodules, uninspectable blobs, archives and Git LFS pointers block. Reviewed binary artifacts are bound to a private path/hash/reason approval, and recognizable embedded text is still checked. The push guard runs before existing upload hooks to avoid uploads occurring before a publication rejection. Public source uses normal CLI arguments and dependencies, and the private contract supplies its run parameters.

Testing found and corrected a Git ignore precedence problem: recursive unignore rules overrode lower-priority nested private exclusions. Opening only each public root directory preserves the nested exclusions. Regression probes now check those paths as well as root private directories. Other tests cover mixed-case internal paths, renamed ZIP/tar/compressed files, secret-bearing refs, commit metadata, historical leaks, chained hooks, linked worktrees and ordinary project terminology such as a model factory.

Audit and certification include applicable publication findings. `verify-publication` returns 44 on a blocked boundary. C93 maps to the live scanner and concrete regressions. Four publication attacks join the release registry; five publication guard deletions join the focused mutation benchmark. Current results and runtime hash are recorded in [validation_2026-10-03.json](validation_2026-10-03.json) and [mutation_checks_2026-10-03.json](mutation_checks_2026-10-03.json).

The bootstrap smoke test initializes and reinitializes a disposable project, commits and pushes to a temporary local bare repository, clones it, checks its exact public file list, and executes its ordinary entrypoint without the private engine. Its artifact is [publication_smoke_2026-10-03.json](publication_smoke_2026-10-03.json). No user's remote repository or published history is changed by these tests.

Private evidence and authorized reviewer bundles remain complete. Public project methods, provenance, limitations, author credits, licenses and required disclosures remain truthful. The agent specifications require separate review of public PR/issue/release prose. Local Git hooks cannot inspect those external surfaces, recognize every semantic paraphrase or stop their owner from bypassing them. Non-Git evidence workspaces explicitly have no publication assurance. The [publication policy](../factory/PUBLICATION_POLICY.md) defines these boundaries and installation steps.
