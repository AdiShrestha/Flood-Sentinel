# Project publication policy — v3.3.0

The public repository describes the project. The installed engine, agent instructions, plans, run state, reviews, keys, audit reports and private transfer bundles stay local. This policy applies to projects bootstrapped with the engine; the engine's own source distribution remains an ordinary tracked repository.

`init` creates Git when necessary, installs a neutral allowlist in `.gitignore`, keeps explicit internal exclusions in Git's local exclude file, and installs private `pre-commit`, `commit-msg` and `pre-push` hooks. Existing executable hooks are chained, including their original push input, and their failures are honored. The publication guard runs before chained pre-push hooks, including uploaders; commit/message checks run after earlier formatters so they inspect their final staged bytes and messages. Initialization refuses a workspace nested inside a different repository. Linked Git worktrees require `extensions.worktreeConfig=true` and receive worktree-specific hook settings; initialization refuses to change shared hook configuration silently. Run `init` again after relocating a project to regenerate local hook paths. Hooks are not shipped in public Git clones; the project owner installs them in each development checkout.

Public roots include `source/`, `src/`, `tests/`, `docs/`, `data/`, `figures/`, ordinary application directories and `.github/`, plus standard project metadata and dependency files. Add necessary root files or directories to the private `project/.factory/publication_policy.json` allowlist, then rerun `init`. Do not make internal paths public. Existing project ignore patterns are retained. Internal names do not appear in the generated public `.gitignore`.

Write public comments and documentation about the algorithm, behavior, design decisions and reproduction steps. Explain scientific methods, data origin, dependencies, limitations and failed or null findings in project terms, for example `docs/methods.md`. Keep orchestration instructions and reviews in `project/`. Public programs accept ordinary CLI arguments such as `--output-dir`, `--seed` and `--experiment-id`; bind these to `{run_dir}`, `{seed}` and `{experiment_id}` in the private launch contract. Programs must not import the private engine or require it in public CI. Public CI tests the project using declared dependencies and normal commands.

Use descriptive commit subjects such as “Fix validation split overlap” and project branch names such as `fix/split-validation`. Avoid internal role names, process narration, internal gate claims, copied prompts, generated assistant chatter and local machine paths in public prose or messages. Public release notes and issue/PR text describe project changes and verification. Inspect those texts before publishing; local hooks cannot inspect GitHub issues, PR descriptions, screenshots or external uploads. Do not fabricate authorship or test claims, remove required notices or author credits, or omit disclosures required by a venue, license or project policy. Publication separation does not change scientific evidence or permit hiding unfavorable results.

Run `python3 -B factory/gatekeeper.py verify-publication .` before release. It inspects the entire index and history reachable from the current branch. Use repeated `--ref` arguments for additional branches or tags; `--staged-only` limits a development check to the index. `--commit-message PATH` also checks a proposed message. A blocked check returns exit 44 and writes a private location/rule report. Audit and certification run publication checks when the workspace is a Git repository. Non-Git evidence workspaces report `NOT_INITIALIZED`; that status provides no publication assurance. Bootstrapped projects normally initialize Git automatically.

Hooks inspect actual staged blobs and exact outgoing object identities. Unstaged edits cannot replace staged bytes during inspection. Pushes check every reachable commit, its tree and message, annotated tag messages, and exposed branch/tag names. Deleting a leaked file in a later commit does not remove it from history. Existing historical leaks block a push; disclose the finding locally and prepare a reviewed remediation. Never rewrite published history or delete scientific evidence automatically to satisfy this gate. Also inspect existing remote branches and tags when assessing an already published repository; hooks govern new pushes, not past remote disclosures.

Paths outside the public allowlist, internal files, forced cache/credential files, unmerged entries, symlinks, submodules, archives, Git LFS pointers, recognizable private metadata, credential markers and uninspectable content fail closed. LFS object bytes and other external uploads are outside the inspected Git blobs and must be reviewed through a separate publication process. Archives are blocked even when renamed because they can conceal private files. Publish inspectable project files instead. Binary project artifacts require a private approval under `approved_binary_artifacts`, keyed by public path, containing their exact `sha256` and a specific `reason` of at least 20 characters. Inspect the rendered artifact and embedded metadata first. Modified bytes require a new review. This approval records a human/agent assessment; the engine does not understand image or PDF semantics. ZIP-based artifacts such as `.npz` must be exported into inspectable files rather than treated as approved opaque archives.

The private `handoff` ZIP intentionally contains engine and evidence files for an authorized reviewer. It is not a public release artifact and must never be committed, attached to a public release or uploaded to a public service. Public reproduction artifacts are purpose-selected project outputs, not a renamed private handoff.

These local checks reduce accidental disclosure. Repository owners can bypass or replace hooks, new clones need local setup, and pattern checks cannot recognize every paraphrase, secret, binary metadata field or unrelated artifact. Server policy and review are required for enforcement against a deliberate bypass. Do not claim that absence of a pattern proves absence of internal references or sensitive information.
