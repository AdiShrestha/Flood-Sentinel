## Receipt authentication and its limits

The stored key scheme must match the receipt scheme. Ed25519 verification uses the stored Ed25519 public key and requires the actual cryptography implementation. An unavailable implementation cannot silently downgrade the stored scheme. HMAC verification uses the private symmetric secret; public metadata stores its SHA-256 fingerprint, not the secret. Historical HMAC public metadata exposed its secret and is rejected. Preserve affected artifacts and arrange explicit key rotation by the owner. Direct defect reproductions used temporary fixture keys. Earlier inherited-suite fallback access is uncertain and recorded under R20; no personal key was intentionally rotated or published. Corrected tests restore their environment, and the final self-test harness uses temporary default keys and blocks personal factory-directory opens.

Audit verifies any supplied signature and binds project, epoch, experiment, seed, nonce, frozen content root, actual input/output inventories, launch digest, interpreter observation, dependency lock and execution times/status to the actual outer run. A valid signature does not excuse incorrect predictions/metrics. Unsigned historical execution can be checked structurally with an explicit UNATTESTED_EXECUTION diagnostic; it cannot acquire an attestation by having a result path. Future Flood Sentinel research must satisfy P00's stronger execution contract before freezing.

The local key remains readable by processes running as its owning OS user. A worker and supervisor sharing that user are not an isolated trust boundary. The current interpreter snapshot is from the supervisor process; legacy child-runtime execution is explicitly unattested. Typed-contract declarations and a signature alone do not demonstrate network isolation, hidden-label protection or trusted execution. No implementation in this patch establishes an independent evaluator or independent scientific reviewer.

## Assurance/status transition

Automatic assurance is BLOCKED on errors and otherwise at most STRUCTURALLY_VALIDATED. A boolean saying review occurred cannot promote independence. After required evidence-bound review, `certify` can write LOCAL_REVIEW_COMPLETE with STRUCTURALLY_VALIDATED assurance. Its successful exit indicates local completion only. Handoff reports LOCAL_REVIEW_COMPLETE when its local record is current, otherwise NOT_CERTIFIED. Older READY_FOR_HUMAN_SUBMISSION_REVIEW records are not current records under this contract. Archive verification proves membership/bytes only; arbitrary status metadata within an archive is not attestation.

Higher levels named in historical schemas/prose are unsupported capabilities, not achieved properties. A stronger backend needs a new versioned contract, identity/key and label isolation, actual child runtime/dependency evidence, negative enforcement tests and review by a separate scientific/technical reviewer. This single-agent audit is a local review and must not be presented as independent scientific review. P00 remains open.

## Numerical/evidence behavior

Output inventories hash all regular files when binary rejection is disabled, including bytecode and binary outputs. Frozen source/data retain dangerous-extension rejection and include cache-directory paths in the inventory; source code cannot evade binding by being stored under __pycache__. Clean bytecode from the frozen payload before freeze, without deleting retained research attempts. No mutable output is exempt from the recorded output-root comparison. Typed entrypoints use the same root-containment guard as evidence paths. Requested memory/process limits now fail if the OS refuses them; launch failures retain an attempt rather than proceed with an unenforced requested limit. Historical `merkle_root` is a flat sorted content digest; no binary-tree membership proofs are claimed.

Unmeasured CPU time and memory are null. Wall duration is recorded by its actual name and scope; no CPU or memory benchmark is inferred from it. Epochs and class counts are integers. Statistical values reject boolean/string coercion, nonfinite values, invalid probabilities/p-values and inverted intervals. F1, precision, recall and ordinary accuracy are not assigned a universal .5 random baseline. Unexpected below-chance AUROC, exact-zero p-values, zero-width intervals or flat sensitivity require investigation, not altered outcomes. A documented flat response can be reported; a desired nonflat result is never required.

Native binary metrics still use the supplied clipped log-loss convention at 1e-15. Flood Sentinel engine v0.2.0 uses exact log loss by default; its explicit `log_epsilon=1e-15` option matches that convention. The runtime/domain adapter must register a consistent policy. Neither an epsilon nor a threshold may be selected to improve test outcomes. Extended/infinite losses need a lossless domain representation; strict JSON rejects bare Infinity. Do not substitute a finite value or unqualified null to satisfy the native finite-result schema.

Tests were not deleted to conceal failures.
