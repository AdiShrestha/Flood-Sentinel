# Gatekeeper implementation contract — v3.3.0

The executable command surface is listed by `python3 factory/gatekeeper.py --help`. Lifecycle commands are `init`, `freeze`, `run`, `record`, `audit`, `certify`, `status`, `handoff`, and `verify-bundle`. Scientific commands include `verify-constitution-coverage`, `verify-coverage-liveness`, `verify-training-sufficiency`, `verify-split-integrity`, `verify-result-plausibility`, `verify-cross-artifact-traceability`, `verify-reproducibility`, `verify-sensitivity-analysis`, `verify-statistical-protocol`, `pre-submission-audit`, `verify-failure-taxonomy`, `acquisition-audit`, `tier-check`, and `check`. `self-check` validates the active installation. `release-certify` combines project certification checks and executed registered attack regressions.

Freeze binds the plan, declared evidence, launch policy and active code/policy hash. Run constructs a typed argv, captures retained execution/output bindings, signs a local receipt, and records verified predictions. Audit reloads current bytes, verifies all required receipt signatures/bindings and recomputes evidence. Certify repeats audit and requires a current evidence-bound review. Each CLI invocation emits one JSON result; `--help` remains argparse help text.

Exit codes are unique by failure domain: 0 success; 11 acquisition; 17 contract shape; 18 tier; 27 statistical protocol; 28 sensitivity; 29 readiness; 30 taxonomy; 31 constitution; 32 training; 33 split; 34 plausibility; 35 traceability; 36 reproduction; 40 release preflight/coverage liveness; 41 lifecycle evidence; 42 lifecycle science; 43 lifecycle review; 44 project publication. Use the JSON status and detail with the invoked command. Exit 0 means that operation passed its declared checks, not journal acceptance.

The coverage matrix checks exact active IDs, callable resolution/reachability and named regression references. Procedural obligations carry explicit limitations. It does not prove semantic equivalence between a principle and a function. The attack registry declares its actual scope and release checks execute its fixtures; passing known fixtures does not prove all attacks fail.

Local assurance remains `STRUCTURALLY_VALIDATED`. A release status can be `READY_FOR_HUMAN_SUBMISSION_REVIEW` after required structural evidence and recorded review pass, while same-user execution isolation, sealed label access and independently verified reviewer identity remain unavailable. The audit, certificate and human digest disclose those limits.

Standalone training uses the shared raw-trace validator; absent a supplied policy it requires a fixed budget of at least 10 epochs and stable two-window tail. Explicit early stopping requires a supported validation event and selected checkpoint. Split checks require integral binary counts and an actual independent-group count; prose justification never waives a numeric floor. Plausibility uses metric-specific baselines, typed p-values and ordered intervals; unresolved investigations block. Traceability requires recognized identifiers and valid sources.

Both `certify` and `release-certify` execute the registered attacks, `run_mutation_checks.py` against disposable copies (80% floor, no infrastructure errors/skips), and `run_seeded_fault_benchmark.py` (36 faulted synthetic QA projects plus matched clean controls). Ordinary `certify` starts preflight only after project audit/review pass and fixture exclusion; `release-certify` forces preflight first, including for validation fixtures. Both save private `project/release_checks.json`; a saved PASS never skips execution. After preflight, evidence and review are revalidated. Certificates bind the report bytes and executable QA corpus, and handoff rejects stale bindings. A baseline or target-resolution error cannot count as a killed mutant. The targeted mutation score is not repository-wide; supported seeded guards must catch their registered flaws, while known label-secrecy/acquisition limits remain explicitly undetected. Conditional per-family binomial intervals apply only to the synthetic generator, not real research projects.

Publication: `verify-publication PROJECT [--ref REF ...] [--staged-only] [--commit-message PATH]` checks actual Git content and returns exit 44 on failure. `init` installs neutral public ignores and private chained Git hooks in project repositories. Audit/certification incorporate publication findings; non-Git workspaces explicitly have no publication assurance. Private transfer bundles remain unsuitable for public release. The check is a local accidental-disclosure guard, not authenticated server enforcement.
